# 工程3：旅行画面と端末内保存

## 画面

| ページ | 動作 |
| --- | --- |
| ホーム | 最近の旅行、旅行情報の3ボタン、過去の旅行の2列カード。最大文字では1列。空の場合は作成へ案内 |
| 旅行一覧 | 保存した全旅行からカードを開いて概要を表示 |
| 旅を追加 | 都市名・表紙プレビュー・日程と同行者の準備欄。日程を開いて開始日と終了日を編集し、保存に成功したら概要を開く |
| プロフィール | 標準アイコン、表示名、旅行件数、訪れた都市。編集シートで保存・キャンセル |
| 友だち追加 | プロフィールから開く案内。実際の検索・招待は工程5 |
| 設定 | 旅行中・写真・プライバシーの準備中項目、端末内保存の範囲、外観とアプリ情報 |

都市マスタは未提供のため、現在は都市名を自由入力し、共通表紙を使います。Figmaの写真はDEBUGギャラリーとデザイン確認モードのサンプルだけに使い、本番の旅行には設定しません。旅のメモ欄はありません。概要からの旅程・スポット・予約情報の編集は工程4で追加します。

## 保存とデータの境界

画面はTripRepositoryを通じて読み書きし、SwiftDataのModelContextを直接操作しません。保存成功後だけ画面用データを更新し、保存エラー時はrollbackして入力画面にエラーを表示します。初期読込に失敗した場合は再試行画面を表示し、既存の保存ファイルを削除したりメモリ保存へ暗黙に切り替えたりしません。

SavedTripはUUID、作成者の内部UUID、都市名、旅行の開始日と終了日を保存します。LocalProfileの内部UUIDは再起動しても維持します。このIDは端末内の仮プロフィールであり、認証済みアカウントではありません。工程5でアカウントへの移行・同期方針を決めます。友だちIDや共有権限を仮発行することはありません。CloudKit自動同期は無効です。

旅行の日程は時刻を持たない暦日として扱い、UTCの午前0時に正規化して保存・表示します。端末のタイムゾーン変更で日付がずれないよう、DatePickerと表示にも同じタイムゾーンを使います。航空便の現地時刻は工程4で別のデータとして設計します。

都市名は空白除去後1〜100文字、プロフィール名は1〜40文字、終了日は開始日以降を必須にしています。同じ日の旅行も作成できます。開始日を後ろに動かすと終了日も追従します。

通常起動はディスクに保存します。DEBUGの `--ui-testing` は独立したメモリ保存で、通常データを読み書きしません。デモギャラリーも実際の旅行データを保存しません。

## 確認手順

1. 通常起動し、空のホームから「旅を追加」へ進む。
2. 都市名と日程を入力し、作成後の概要を閉じる。
3. ホームと旅行一覧の両方から同じ旅行を開く。
4. アプリを終了・再起動し、旅行が残ることを確認する。
5. プロフィールを編集して保存する。再度開いてキャンセルし、保存済みの名前が変わらないことを確認する。
6. 友だち追加と設定の案内を開く。
7. `--large-text` / `--dark-mode` をそれぞれ追加して表示を確認する。

主要操作は文字付きボタンを使用し、旅行カードのリンクには行き先・期間と「旅行の概要を開きます」のヒントを付けています。プロフィール写真は標準アイコンです。

## 検証記録

Xcode 27.2 / iPhone 18 Pro / iOS 27.2で検証しています。

- ビルド成功。保存ファイルを開き直す単体テストで、旅行・プロフィール・作成者IDの保持を確認。
- 初回UIテストで、旅行作成後に入力フォーカスが残りキーボードがタブを覆う問題を検出。保存時にフォーカスを解除するよう修正し、端末操作でホームへの復帰を確認。
- 通常の旅行作成、概要表示、ホーム・一覧の切替、プロフィール保存、設定表示を端末操作で確認。
- アクセシビリティ階層で、旅行カードが都市名・日程を持つボタンとして認識されること、主要操作の日本語ラベルを確認。VoiceOverの音声での読み上げは未検証。
- 工程3で追加したSF SymbolsもApple CoreGlyphsで導入年を確認（2019〜2020年、iOS 13〜14）。iOS 17実機・ランタイムでの実行は未検証。

全体テストは17件中16件が成功しました。最大文字のUIテストで画面外の作成ボタンを直接探していたため、入力完了後にフォームをスクロールする操作を追加しました。最終修正後に影響範囲のUIテスト3件（通常、最大文字＋ダーク、既存ギャラリー）を再実行し、すべて成功しています。未解消のテスト失敗はありません。

最大文字＋ダークでは、作成フォーム下部までのスクロールと作成、ホーム・一覧からの概要表示、プロフィール保存・キャンセル、友だち追加・設定への移動をUIテストで確認しました。テスト添付画像でもホームカード・プロフィール・フォーム下部の文字が折り返して表示されることを確認しました。空状態の強調ボタンはダーク時に黒文字へ切り替え、淡い青の背景に対する読みやすさを改善しています。

## レビュー指摘への対応（2026-11-28）

[PR #3のコメント](https://github.com/MTowa/Trip-App/pull/3#issuecomment-7223792912)を受け、Figmaの日本語版5画面を再取得して見直しました。標準UIの採用は画面構成・配色まで省略する理由にはならないため、今回のPRで修正しています。

| 対象 | 反映した内容 |
| --- | --- |
| 共通 | 明るい青から濃い青への背景グラデーション、紺色の文字、白いパネル、丸みのある書体・角丸。ダーク用の色も定義 |
| ホーム | 最近の旅行→旅行情報（旅程・スポット・予約情報）→過去の旅行。すべて見るから一覧へ移動 |
| 旅行一覧 | 日付の両端表示と区切り線、横長カードの間隔 |
| 旅を追加 | 行き先、Figmaから取得した地図イラスト付き表紙プレビュー、日程と同行者の準備欄、作成ボタン |
| プロフィール | 大きな標準アイコン、集計パネル、訪れた都市、一緒に旅した人の案内、ヘッダーの編集導線 |
| 設定 | 旅行中・写真・プライバシーの分類、アイコン付き白い項目パネル |

### 意図して残している差分

- TabView / NavigationStack / Form、日付選択、SF Symbolsは指示書どおり標準UIを使用します。OSによりタブ・ナビゲーションの外観や余白は変わります。
- FigmaのZen Maru Gothicは同梱せず、Dynamic Type対応の標準フォントにrounded指定を使用しています。
- 都市写真の本番マスタは未提供のため共通表紙です。Figmaにある人物・国・同行者のサンプル数値は実データとして表示しません。旅行回数は保存件数、訪れた場所は終了済み旅行の都市名、未登録の国・同行者数は「—」です。
- 招待・通知・写真共有等はまだ実装していません。設定項目には「準備中」と明示し、実際には働かないトグルは置きません。旅行一覧の更新アイコンはローカル保存に不要なため、作成ボタンにしています。
- 最大文字では複数列を1列に変更し、カード・パネルの高さを内容に合わせて伸ばします。

### 今回の検証

- ビルド成功。
- 通常表示と最大文字＋ダークのUIテスト2件が成功。日程画面への往復とDatePicker2つの存在、作成→概要→ホームの「すべて見る」→一覧→プロフィール保存・キャンセル→友だち追加→設定のスクロールを確認。
- 最終実行はXcode連携ツールの集計が未実行と表示しましたが、xcresulttoolで結果ファイルを直接確認し、Passed・成功2・失敗0を確認しています。
- テスト添付画像でカード・作成ボタンの文字折り返しとダーク配色を確認。
- シミュレータで5画面を撮影し、取得範囲に文字の重なりや欠けがないことを確認。日程画面への遷移も確認しましたが、手動操作中に予期しない日付変更・画面移動があり、戻る操作は手動検証の成功には数えていません。日程画面への往復は自動UIテストにも追加しています。
- `--design-preview` でメモリ保存のサンプル旅行3件を表示できます。通常データには触れず、Releaseでは使いません。写真の権利確認は本番マスタ採用時に必要です。
