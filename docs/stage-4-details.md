# 工程4：旅行の詳細と参加者の編集範囲

## 合意した権限

参加者は自分の座席のみ編集できます。旅程・スポット・予約の共通情報と他人の座席は閲覧のみです。作成者は旅行全体と全員の座席を編集できます。作成者権限の譲渡・共同作成者は追加していません。

| 操作 | 作成者 | 参加者 | 未招待ユーザー |
| --- | --- | --- | --- |
| 詳細の閲覧 | 可 | 可 | 不可 |
| 行き先・旅行日程の変更 | 可 | 不可 | 不可 |
| 旅程・スポット・予約の追加／編集 | 可 | 不可 | 不可 |
| 自分の座席の変更／解除 | 可 | 可 | 不可 |
| 他人の座席の割当／変更／解除 | 可 | 不可 | 不可 |

画面のボタン表示だけでなく、TripDetailStoreの保存メソッドでも権限・旅行への参加・予約種別を検証します。現在は端末内のIDによる制御です。認証・招待・共有は工程5で実装し、同じ制約をサーバー側でも検証します。端末内の検証をサーバーのアクセス制御の代わりにはしません。

## 画面と入力

作成直後の概要、ホーム、保存済みの旅行の概要から、旅程・スポット・予約情報を開けます。3区分を切り替え、既存項目を開いて編集できます。追加・編集は値のコピーをフォームに渡し、保存時のみ書き込みます。キャンセルでは元データを変更しません。

| 種類 | 主な入力 |
| --- | --- |
| 旅行 | 行き先、開始日、終了日。既存の予定・予約の日時は自動移動しない |
| 旅程 | 予定名、集合場所、開始・終了日時、タイムゾーン |
| スポット | 名前、住所・最寄り駅、カテゴリ、任意の緯度・経度 |
| 飛行機 | 名前、予約番号、出発・到着空港、航空会社、便名、出発・到着日時とそれぞれのタイムゾーン |
| ホテル | ホテル名、予約番号、住所、任意の座標、チェックイン・チェックアウト日 |
| その他の予約 | 名前、予約番号、場所、開始・終了日時、タイムゾーン |
| 座席 | 参加者別の座席。空欄で保存すると割り当て解除 |

予約の種類は追加時に選択し、保存済み項目の種類は変更しません。便名等の共通項目をTripEntryに、座席をbookingIDとmemberIDを持つSeatAssignmentに分離しています。メモ欄は追加していません。

## 日時と場所

航空便の日時は絶対時刻とIANAタイムゾーンIDを保存し、出発地・到着地ごとに現地時刻を表示します。タイムゾーンを変更すると同じ瞬間をその地域の表示へ変換するため、フォームにもこの挙動を説明しています。到着の絶対時刻が出発より前の場合は保存できません。

ホテルの日付はUTCの暦日に正規化し、日付のみを表示します。タイムゾーンは航空便と同じ意味ではありません。

スポット等の座標がある場合は座標を優先し、住所のみの場合は住所検索のApple Maps URLを生成します。URLComponentsで日本語や記号をエンコードします。両方がない場合は地図ボタンを出さず、作成者には編集を案内します。位置情報の取得権限は要求しません。

iOS 18.4以降は[Unified Maps URLs](https://developer.apple.com/documentation/mapkit/unified-map-urls)のplace/coordinate/nameとsearch/queryを使い、iOS 17〜18.3では従来のMap Links（ll/q）へ切り替えます。

## 保存

SavedTrip / LocalProfileは維持し、旅行IDをキーにSavedTripDetailを追加しています。詳細はCodableのTripDocumentをDataとしてSwiftDataへ保存します。保存成功後だけ画面用スナップショットを更新し、エラー時はrollbackします。読み込み・デコードに失敗した場合は既存データを消去せず、既存の読込エラー画面に移ります。

## デザイン

Figma日本語版の詳細一覧・旅程追加・スポット追加・予約追加を参照しました。工程3の背景グラデーション、紺色の文字、白いパネル、角丸を共用します。標準のフォーム、日時選択、ナビゲーション、SF Symbolsで実装します。

Figmaの自由入力の日付は実際の日時選択に置き換えています。入力例を本番データとして自動投入するボタンは設けず、DEBUGの専用モードで確認します。飛行機・ホテルの必須項目を扱うため、予約フォームは種類に応じて伸び、スクロールできます。

## 検証用データ

DEBUG起動引数 `--details-preview` で作成者、`--participant-preview` で参加者の画面を確認できます。いずれも独立したメモリ保存にサンプルのフライトと参加者を作り、通常の保存データを変更しません。Releaseでは役割切り替えやサンプル投入は無効です。

1. ホームの予約情報からサンプルのフライトを開く。
2. 作成者モードでは共通項目の編集と、作成者・参加者の座席編集を確認する。
3. 参加者モードでは共通項目の編集と追加ボタンがなく、自分の座席のみ編集できることを確認する。
4. 作成者モードでスポット・旅程・ホテルを追加し、保存後に再度開いて編集する。
5. `--large-text --dark-mode` を追加して文字の折り返しとスクロールを確認する。

## 検証記録

Xcode 27.2 / iPhone 18 Pro / iOS 27.2で検証。

- 初回全体テスト25件中22件成功。新規の座席UIテスト3件は、座席番号だけのStaticTextを探す検証コードが原因で失敗。実際の階層は「参加者サンプル、12A」で、保存・反映を確認できたため、行のラベルを検証するよう修正。
- 最終修正後の影響範囲12件（詳細の単体テスト6件、詳細UI3件、既存ページUI2件、ギャラリーUI1件）がすべて成功。未解消の失敗なし。ビルドも成功。
- Swift Testingで作成者・参加者・未招待ユーザーの権限、座席の分離、入力検証、工程3からの移行・再読込、現地時刻表示、Maps URLのエンコードを確認。
- シミュレータ操作で旅程の追加、ホテルの作成と詳細再表示、航空便の出発・到着の現地時刻表示を確認。取得範囲に文字の欠け・重なりなし。
- 手動確認中にデバイス操作セッションの消失が1回あり、再作成。手動での編集保存・参加者の座席変更は成功扱いにせず、自動テストで検証。
- iOS 17実機・ランタイムでの実行、VoiceOver音声、認証・共有サーバーでの権限制御は未検証。
