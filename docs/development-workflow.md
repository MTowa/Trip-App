# ブランチ・PR命名規則

Trip Appの全工程で使用する開発ルールです。変更が必要な場合は、この文書もPRで更新します。

## ブランチ

工程ごとに専用ブランチを作成し、形式は `stage-<工程番号>-<種別>-<内容>` とします。半角英小文字、数字、ハイフンを使用し、内容は短い英語で表します。日付・個人名・日本語・空白は使用しません。

| 種別 | 用途 | 例 |
| --- | --- | --- |
| chore | 開発環境・設定 | stage-1-chore-project-setup |
| feat | 機能追加 | stage-2-feat-trip-components |
| fix | 不具合修正 | stage-4-fix-reservation-time-zone |
| docs | 文書のみの変更 | stage-2-docs-destination-images |
| test | テストのみの変更 | stage-4-test-participant-permissions |
| refactor | 動作を変えない整理 | stage-3-refactor-trip-repository |

工程1の `stage-1-project-setup` は、この規則を導入する既存ブランチのため例外として維持します。以後の新規ブランチには種別を含めます。

mainはレビュー済みの変更を置くブランチです。通常は最新のmainから作業ブランチを作成します。

```sh
git switch main
git pull --ff-only origin main
git switch -c stage-2-feat-trip-components
```

前の工程がレビュー中で、その変更を必要とする場合は前工程のブランチから次工程を開始できます。その場合、PRの比較先も前工程のブランチにし、依存するPRを本文に明記します。前工程のマージ後に比較先をmainに変更し、差分とビルドを再確認します。

## PRタイトル

形式は `<種別>(stage-<工程番号>): <変更内容を日本語で簡潔に>` とします。種別はブランチと同じ分類です。

| 例 | 対象 |
| --- | --- |
| chore(stage-1): iOS 17向けの開発環境とGit管理を整備 | 工程1 |
| feat(stage-2): Trip Cardと共通コンポーネントを追加 | 工程2 |
| feat(stage-3): 旅行一覧と端末内保存を実装 | 工程3 |
| fix(stage-4): フライトの現地時刻表示を修正 | 工程4 |

タイトルには実際の最終差分を表す内容を書きます。作業途中に対象が変わった場合は、タイトルと本文を更新してください。

## PR本文

リポジトリのPRテンプレートを使用し、次の情報を記載します。

- 対象工程、変更理由、利用者にとって変わる動作。
- 再現可能な確認手順。前提データやアカウント種別が必要な場合は明記。
- Xcode・端末・iOSバージョン、ビルドとテストの実施結果。
- 画面変更がある場合のスクリーンショット。個人情報や予約情報はテスト用のものを使用。
- 未検証項目、残課題、依存するPR。

実施していないテストを成功扱いにしないでください。設定変更だけで画面が変わらない場合は「画面変更なし」と記載できます。

## レビューとマージ

1. 実装・ビルド・必要なテストを行い、工程ごとのPRを作成します。
2. 未完了項目がある場合はDraftにし、完了条件を記載します。
3. 依頼者が変更内容と検証結果を確認します。
4. 明示的な承認を受けてからmainへ取り込みます。自動マージは設定しません。

空のリポジトリでPRを作成するための初期コミットにはアプリの変更を含めません。アプリと設定の導入は工程1のPRでレビューします。

## コミット

コミットは `<種別>: <変更内容>` を基本とし、一つの目的にまとめます。例: `chore: configure iOS 17 project and shared scheme`。

個人のXcode設定、DerivedData、ビルド成果物、秘密鍵、認証情報はコミットしません。共有スキーム、ソース、アセット、プロジェクト設定、文書はGitで管理します。
